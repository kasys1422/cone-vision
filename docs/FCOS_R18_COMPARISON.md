# FCOS ResNet-18とResNet-50の比較

512px単体検出器の比較。ResNet-18は採用判断用の候補として学習した。

| 実写テスト43枚・63個 | ResNet-18 | ResNet-50 |
|---|---:|---:|
| 検出器のパラメータ数 | 13,651,910 | 32,062,150 |
| Web用検出器のバイト数 | 27,592,422 | 64,569,685 |
| PC単一スレッドWASM、画像1枚あたりの中央値 | 826 ms | 2,152 ms |
| 正検出 / 誤検出 / 見落とし | 47 / 4 / 16 | 55 / 3 / 8 |
| 96px未満の正検出 | 0/7 | 2/7 |
| 空画像21枚での誤検出 | 0 | 0 |
| mAP@50 / mAP@50:95 | 81.98% / 47.14% | 92.09% / 73.46% |
| 許容誤差内の実写特徴点（未検出込み） | 40/63点 | 44/63点 |

両モデルを同じPCで順番に再測定。ONNX Runtime Web 1.22.0のWASM、Node.js、OpenCV.js、共通の192px特徴点モデルを使用。時間は前処理・検出・特徴点までを含み、モデル読込、写真デコード、画面描画を除く。実写テストには校正値と距離の真値がなく、メートル単位の測距精度とスマートフォン速度は未評価。しきい値0.50、NMS・正解対応IoUとも0.50。APは同じ配布用ONNXをCPUで実行し、スコア0.01以上を既存キットの101点補間で集計した。

96px未満の7個は4枚に分布。T0512の74pxと60pxをResNet-50だけが検出した。支柱のあるT0020では両方とも左・中央のコーンを検出、支柱の誤検出は0。合成サンプル3枚の計4個では、測距の品質判定を通ったのはResNet-18が2個、ResNet-50が4個。ResNet-18は複数コーンサンプルの2個を見落とした。

## 学習条件

既存グループ分割の実写356枚で学習、107枚で検証。ResNet-18はImageNet事前学習済みバックボーンと新規初期化の幅128の5段FPN・検出ヘッドを使用。ResNet-50はCOCOで検出まで事前学習済み。両者は初期重みの条件も異なる。ResNet-18はRTX 5080で10エポック学習し、固定しきい値の検証F1で10エポック目を選択した。検証は正検出133/270・誤検出25・小型43/156。既存のResNet-50は201/270・10・98/156。

再学習はV12開発キットの分割ラベルとTraConの元画像ZIPを用い、リポジトリ直下から実行する。

```sh
python scripts/train_fcos.py PATH_TO_SPLITS TraCon-upstream.zip OUTPUT_DIR --backbone resnet18
```

出力先の best.pt はPyTorch重み、cone_detector.onnx はWeb用の重み圧縮済みモデル。今回のWeb用候補のSHA-256は 1fe727add743b0998f8d3e38032ad5a579e73d8441d2af4ec97d526367740ca2。
